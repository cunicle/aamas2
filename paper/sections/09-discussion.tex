\section{Discussion, Limitations, and Conclusion}
\label{sec:discussion}

\paragraph{Beyond one agent.} Nothing in the analysis of Section~\ref{sec:setup} depends on diffusion. Whenever several decisions are taken at once by deciders that cannot see each other's choices, the three cases of this paper apply. A convention that all deciders share, such as the order in which a request names its entities, assigns the roles and makes simultaneous moves safe. Symmetric roles collide unless the deciders take turns. And a shared feature that the designer did not intend as a signal, such as the length of a slot, is read and obeyed, so a wrong value of it mis-binds even decisions taken one at a time. Multi-agent LLM systems in which several workers claim subtasks of a shared plan at the same time~\cite{mao2026delm,rodionov2025hogwild} face the same three cases, with the format of the plan in the place of the skeleton. Section~\ref{sec:symmetric} shows the second case in teams of LLM agents: agents that act at once collide on a shared focal point whether they are numbered or sample, and agents that take turns never collide. Such systems need turn-taking, or a shared order that assigns the roles, rather than role names in the prompt.

\paragraph{Limitations.} The oracle skeleton fixes the number of calls, their tools, and their argument names, so our numbers isolate the values and do not describe a deployed agent: without the skeleton, \dream reaches 75.3\% set accuracy at $k=2$, against 88.0\% with it. Exact lengths also tell the model which value goes where; the length-symmetric requests (Section~\ref{sec:ordered}) and the swap (Section~\ref{sec:masquerade}) control for this, but no skeleton removes it. We tested two dLLMs with greedy decoding only, and ran \llada on subsets of 100 requests (surplus and estimated lengths) and 34 requests (swap), where differences of a few points are within noise \tbd{(confidence intervals)}. The open choose-N variant gives each city one token, which limits which cities a slot can write, so we report only its duplicates. We did not run a prompted placeholder baseline in the style of S$^3$~\cite{xiong2026s3}, the length search of CAL~\cite{liu2026cal}, or the closing bias together with estimated lengths. Finally, the skeleton tokenizes the fixed text around each slot on its own, so its token boundaries can differ from those of free generation.

\paragraph{Conclusion.} A dLLM agent that issues several tool calls in one turn coordinates them the way players who cannot talk do. When the request orders its entities, the order is a focal point, and committing many tokens per step costs little. When nothing tells the calls apart, same-step commits collide, and taking turns avoids the collisions. The most costly failures come from the action interface: the agent reads the number of masks in a slot as a promise about the length of its value and keeps the promise, so a slot of the wrong length gets a value of the wrong size or a sibling's value, even with one token per step. These errors look like the failures blamed on parallel decoding. Designers of dLLM agents should get slot lengths right before they give up parallelism, and evaluators should control slot lengths before they blame it.
