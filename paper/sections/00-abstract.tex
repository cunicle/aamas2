When an agent issues several tool calls at once, or a team of LLM agents splits a task, each decision must take its own role without seeing the others. We study where such roles come from, using diffusion language models (dLLMs) as a controllable test bed: a dLLM agent fills the value slots of a fixed call skeleton and can commit any number of slots in the same step, so its decoding schedule sets who moves together and who sees what. We compare its slots with teams of LLM agents on the same requests. On the parallel calls of the Berkeley Function Calling Leaderboard, slots that move together coordinate on the order in which the request mentions its entities: committing 16 tokens per step instead of one costs Dream-7B 5 points of set accuracy. Agents that act at the same time cannot use this order, even when numbered (28.8\% set accuracy against 81.7\% for same-step slots) or told the convention (48.1\%); agents that take turns match the single agent. When nothing orders the choices, simultaneous slots and agents collide, sampling does not help, and turn-taking does, as does a confidence threshold that commits uncertain choices one at a time. The strongest cue is the slot length: a decider reads the number of masks as the length of its value, which assigns roles when the lengths are right and swaps them when they are wrong, even one token per step and for a single agent. A closing delimiter written after each slot doubles the cost of one extra mask, but half of it remains when the model writes the delimiter itself. Errors from wrong lengths look like failures of parallel decoding, so evaluations of such agents must control slot lengths before blaming parallelism.
