## 六、实验 C 的结果（10-04 合并，关键数字已从原始记录复算）

**C1：有序请求，104 条，兄弟调用的单调用骨架完全相同，set accuracy**

| | Dream | Qwen |
|---|---|---|
| 一张画布，k=16 | 81.7 | —（AR 画布 91.3） |
| 一张画布，k=1 | 88.5 | — |
| 团队：同时、匿名 | 0.0 | 0.0 |
| 团队：同时、编号 | 28.8 | 0.0 |
| 团队：同时、明确告知约定（sim-rule） | 48.1 | 34.6 |
| 团队：轮流 | 84.6–85.6 | 88.5 |

结论：同时行动的画布槽能利用提及顺序，同时行动的 agent 不能；给编号不行，明确告诉规则也只能部分做到；轮流行动的团队与画布持平。choose-N list 上的 sim-rule 也一样（撞车率 Dream 45%、Qwen 70%）。

**C2：槽长对单个 agent，165 条**
- exact 槽长下，同时、匿名的 Dream agent 有 48.5% 做对（C1 骨架完全相同时是 0%，Qwen 是 0.6%）：槽长本身就能给 agent 分配角色。
- swap 下，被改变的槽有 89.1% 写入长度合适的兄弟值（画布上是 79.4%）；轮流行动时也有 84–85%。单个 agent 照样服从错误的槽长。

**C3：收尾符对照（Dream）。两种解释各占一部分，原界面的效应约有一半来自预写的收尾符**

| | 原界面 | 变体（模型自己写收尾符，空格填充） |
|---|---|---|
| exact，k=1 的 set accuracy | 89.8 | 70.3（变体自身的问题：7.6% 的槽不收尾，或写成 `}}`、`",` 这类合并 token） |
| +1，k=1，槽只含自己的值（逐槽读） | 37.5 | 62.5（变体 exact 时为 89.9） |
| +1，k=1，overfill | 44.4 | 26.2 |
| swap，被改变的槽写入合适兄弟值（逐槽读） | 79.4 | 49.2 |
| 单侧加长：加长的槽写入兄弟的值 / overfill / 自己的值 | 35.4 / 20.2 / 21.8 | 14.0 / 23.9 / 40.3 |
| 探针 P(收尾)，s=1 / 2 / 8 | 1.0 / 3.3 / 74.0 | 43.0 / 34.5 / 81.6（s=0 时 60.5） |
| 探针 s=1，整数 / 浮点 / 字符串 | 0.9 / 0.2 / 0.5 | 19.3 / 14.5 / 69.9 |

- 变体里 set accuracy 仍呈 U 形：exact 70.3，+1 26.8，+2 16.8，+8 39.5。
- 数值类型即使没有预写的收尾符也很少提前收尾，这正是“金额 ×10”问题的来源。
- 单侧加长在原界面下，加长的槽写入兄弟值（35.4%）比写入自己的值（21.8%）更多，而兄弟的槽 90.9% 保持自己的值。这一部分无法用“避免重复”解释。

**C4：choose-N 上的置信阈值（与预测相反）**
- τ=0.9 与 k=1 结果完全相同：list 100% 正确，open 0% 撞车。从左到右也不撞车。
- 原因：对称的选择让各位置的置信度都低于阈值，阈值解码就退回到每次只提交一个。置信阈值会自己判断该并行还是该轮流。
