## 二、CPU 分析清单（不需要 GPU，写作这边做）

1. 等长子集（Dream 213 条、LLaDA2.0 216 条）上 k=1 与 k=16 的 set accuracy 和 CCER，带配对区间。
2. BFCL 上兄弟槽对在同一步提交的比例（各 k），以及只看这些请求时的 CCER。
3. estimate、k=16 的 CCER 及分类（补成 2×2），以及 k=16 的跨调用错误里有多少在 k=1 下仍然存在。
4. swap 分层：方向（槽变长或变短）、长度差（1、2、3–4、≥5）、类型（字符串或数值），给出计数。
5. 槽层面比率（95.4/92.0、34.0、35.1、79.4、47.5）的按请求聚类 bootstrap 区间。
6. AR 截断审计：exact 槽长下被截断的值有多少；BFCL 接受、但 token 长度与参考值不同的值有多少。
7. surplus 的代价按参数类型拆开（数值、字符串、其他）。
8. Order 用固定分母重算（解析失败算作不按顺序）。
9. choose-N：城市选择的分布、第一步 top-1 概率或熵；均匀混合基准。
10. 多重比较：做 Holm 校正，或者声明较小的检验是探索性的。

## 三、文字修改清单（零碎问题）

- “symmetric”有两种用法：BFCL 的等长请求改称 “equal-length”，表 1 的 “CCER (sym.)” 改成 “CCER (eq. len.)”；“symmetric”只留给 choose-N。
- 摘要里的“90%→16%”和“79%”要写明模型是 Dream；LLaDA2.0 的子集数字（92.0→16.0）要注明是 100 条子集，全集 exact 是 87.8%。
- §7 的“13.9% 受影响轮次 vs 1.0% 全部轮次”分母不同：改用同一批 165 条在 k=16 exact 下的值。§7 的 33.3% 和 19.8% 要写明 k。
- §2 里 “DreamOn …, DIA …” 那句缺引用编号，补上。Other-Play 的描述改正：它是为了**避免**独立训练的伙伴不会共有的任意约定，而不是“利用对称性”。
- §8 建议 (2)：注明置信阈值识别不了对称情形，在对称请求上没有测（C4 会补）；“块解码几乎能避免”改成“LLaDA2.0 几乎能避免，但块不是全部原因”。
- §9：“多 agent 系统面临同样的三种情况”改成预期；“需要轮流而不是编号”限定在我们的设定（两个 7B 模型、一种措辞）。
- 局限部分补上：
  - commit 顺序用的置信度分数是什么；
  - “exact”用的是 BFCL 的哪个可接受值；
  - 长度估计是建立在有偏的收尾概率上的启发式方法；
  - LLaDA2.0 没有用它原生的工具调用格式；
  - 两个模型的分词器不同，所以“+1 个 mask”对它们不是同一种扰动；
  - 没有测变长 dLLM（DreamOn）；
  - 长度实验只用贪心解码。
- 区间说明：单个比率用的是 Wilson 区间，成对比较用的是 bootstrap 区间，§3.4 要写清楚。
- 相关工作可以考虑补三篇：NAR 生成的多模态与重复问题（Gu et al., ICLR 2018）、Mask-Predict 的长度预测（Ghazvininejad et al., EMNLP 2019）、匿名进程的对称性破缺（Angluin, STOC 1980）。**引用前必须按 `references.md` 的规则逐篇核对。**
- R1 建议的标题：*Masks Are Length Promises: Action Interfaces, Not Parallel Decoding, Drive Cross-Call Errors of Diffusion-LM Agents*。是否改标题，等实验 C 的结果出来、用户决定后再定。
