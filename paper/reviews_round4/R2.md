# Review of AAMAS 2027 submission 1241 (Reviewer 2)

"Acting in Parallel Without Talking: Focal Points, Collisions, and Length Signals in Diffusion-LM Agents and LLM Agent Teams"

What I checked: I read the PDF and the LaTeX sources and unzipped the supplement into my own working directory. I ran `scripts/reproduce_paper.sh` on CPU, offline, using the cached tokenizers. `out/tables` is byte-identical to `expected/tables` and to `paper/tables`, and every file in `results/summary/` matches the released summaries. All 121 unit tests pass. I also checked the in-text numbers against the records: all 101 percentages in the body text appear in the summaries, and I recomputed roughly 60 of them by hand. I wrote my own analyses of the released records. They are cited below as "(my analysis)", and the scripts are in my work directory under `an/`.

---

## 1. Summary

The paper uses a dLLM agent that fills value slots of an oracle tool-call skeleton as a test bed for parallel deciders that cannot see each other. It compares the slots with teams of 7B LLM agents that each make one call. There are three hypotheses:

- **P1.** When the request orders its entities, same-step slots follow mention order. At k=16, Dream loses 5.3 points of set accuracy relative to k=1 (89.8 to 84.5). Simultaneous numbered agents reach 28.8% (48.1% when told the rule). Dream "position agents" reach 85.6%.
- **P2.** When nothing orders the choices, simultaneous agents collide. This is tested on choose-N weather requests.
- **P3.** Slot length is a cue. Surplus masks are filled with content. Swapped lengths rebind values to the wrong calls even at one token per step. Two interface choices are partly isolated: the pre-written closing delimiter (via a "closing token in the slot" variant) and the type mask (via format-tolerant slots).

Section 7 argues that wrong lengths produce cross-call errors that look like failures of parallel decoding. With model-estimated lengths, CCER is 6.5% at k=1 against 2.0% at k=16 with exact lengths. Section 8 gives design and evaluation recommendations, including a one-pass length estimate and a closing-logit bias.

## 2. Strengths

1. **Careful controls.** The paper uses:
   - equal-length subsets, so that lengths cannot identify calls;
   - a "one slot longer" intervention, which separates length fit from a moved sibling;
   - the closing-token-in-slot and format-tolerant variants;
   - LLaDA2.0 as a block-causal control;
   - a matched AR reference (Qwen2.5-7B-Instruct, the instruct sibling of Dream's initialization) decoded in the same skeleton with the same type mask.
2. **Paired design and candid reporting.** Comparisons are on the same requests, with exact McNemar tests and Holm's correction. Non-significant results are reported as such: Dream canvas duplicates on choose-N have Holm p=0.059, and LLaDA2.0's estimate contrast is not significant after correction. Choosing beta on the evaluation set is flagged as optimistic.
3. **Exemplary reproducibility.** Every table rebuilds byte-identically from the raw records on CPU. The records include full decoding traces, top-5 probabilities and slot lengths, which made every reanalysis below possible. Figure 1 is a verbatim record (`parallel_20` in `bfcl_skel_k`, `bfcl_surplus` s=1 and `bfcl_swap`, all at k=1).
4. **Robust core findings.** Slot length is a strong cue, and wrong lengths rebind values at one token per step. My reanalysis makes this stronger, not weaker (W1b, W6).
5. **Practical evaluation protocol.** Section 7's advice is simple and useful for the dLLM-agent community: decode at k=1 under the agent's own length policy before blaming parallelism.

## 3. Weaknesses (most serious first)

### W1. The cross-call taxonomy and set scoring distort the "masquerade" evidence (Sec. 3.4, Sec. 7, Table 4)

**(a) "Shared" counts single-value corruption as a cross-call error.**

> "an argument that the reference shares across calls but the prediction does not" (Sec. 3.4)

`taxonomy.py::diagnose` adds `inconsistent_shared_arg` whenever the matched predictions of a shared argument differ and any one of them is wrong. A single overfilled or truncated value in one call is therefore a cross-call error. So is a forced optional default, where both calls accept `['', 0]`. Examples from the records:

| Request | Condition | What happened |
|---|---|---|
| `parallel_21` | estimate k=1 | crime "Money Launder" (truncation) |
| `parallel_14` | estimate k=16 | interest_rate 0.050000005 (overfill) |
| `parallel_32` | LLaDA2.0 +1/+8 | start_year 1861 / 1789, where the reference default is 0 |
| `parallel_156` | LLaDA2.0 +1 | data "data_random_forest1..4" (overfill with an index) |

Requests whose only cross-call label is Shared (my analysis):

| Condition | Shared-only / all CCER requests |
|---|---|
| Dream exact k=16 | 3/8 |
| Dream estimate k=1 | 8/26 |
| Dream estimate k=16 | 15/41 |
| Dream +1 k=1 | 6/11 |
| LLaDA2.0 estimate k=1 | 6/12 |
| LLaDA2.0 +1 k=1 | 4/7 |

Dropping Shared-only requests:
- The headline contrast survives: estimate k=1 4.5% vs exact k=16 1.25%, discordant 17/4, McNemar p=0.0072 (uncorrected).
- The claimed interaction does not survive (see W4).

The label mixes genuine scope disagreements (e.g. `parallel_45`: "Australia" applied to one call only) with single-call corruption. It should be split.

**(b) Set scoring hides most length-driven rebinding.**

Table 3 reports 67.3% set accuracy for the swap, and Sec. 7 reports CCER 15.2%. But the authors' own `review_numbers.md` shows that 108 of the 111 correct swap outputs are "correct only as a reordered set". By my count, 141/165 (85.5%) swap requests have at least one changed slot holding a sibling's value. Of these, 108 are scored correct and only 25 count as cross-call errors. So CCER captures about 18% of the rebinding the swap causes. The paper never states this, and

> "The rotated sibling group follows the length while the other arguments of the call follow the order"

describes only the 25-request minority. The same applies to the agent rows of Table 3 (46.7% / 75.8% set accuracy with 89.1% / 84.2% sibling-fit).

**(c) The chimera detector covers strings only, and its k=1 hits look like false positives.**

All six chimera detections at k=1 are overfills, garbles or truncations rather than splices: "202021-01-01", "202018-01-01", "2022-022-01-01", "Los Angeles County Court, Los Angeles", and "Chica, USA" twice. Numeric slots are about 42% of all slots and are never checked. Because chimeras are rare this does not change the conclusions, but "Splices are rare" should be qualified.

### W2. Oracle-skeleton confounds beyond those discussed, and a mis-attributed limitation (Sec. 3.1, 3.4, 9)

**(a) Optional arguments are forced to reference defaults.**

`build_skeleton` includes "every parameter with at least one non-empty acceptable value". This covers 315 of 3,063 slots (10.3%) in 169 requests whose acceptable set includes `""`, i.e. optional arguments. The skeleton forces these to the reference default (`year: ['',0]`, `end_year: ['',2000]`, `level: ['user','']`, `"metric"`, `True`, ...). The exact slot length then leaks that arbitrary default.

Requests whose only errors lie in such slots (my analysis):

| Condition | Failures only in forced-default slots / all failures |
|---|---|
| Dream exact k=1 | 8/41 |
| Dream +1 | 12/338 |
| Dream estimate k=1 | 13/231 |
| Qwen exact | 10/54 |

These are often semantically better answers: Qwen with +8 writes `year: 1215` for Magna Carta and is marked wrong.

**(b) The limitation attributes the AR cut-off to the wrong cause.**

> "Exact lengths come from the reference values tokenized on their own, which can be shorter than in context: lifting the AR agent's cut-off with eight extra masks changes its output in 44 of 400 requests" (Sec. 9)

The skeleton is tokenized in chunks that break at the slot boundaries (`flush()`). Standalone tokenization of the value matches the natural in-context tokenization of the gold JSON for:
- all 1,014 integer, 281 float and 103 boolean slots;
- 1,446 of 1,464 string slots.

The exceptions are 122 of 201 array slots, where the canvas is one token **longer** than natural (`"]` + `,` instead of `"],`) (my analysis).

The 44 changed AR outputs come instead from two sources:
- **First-acceptable-variant lengths** (`oracle_lengths` uses `vals[0]`):
  - `parallel_6`: 'Ill' for ['IL','Illinois'];
  - `parallel_17`: 'GOO' for ['GOOG','GOOGL'].
- **The forced optional defaults in (a):** `parallel_31/32`, where `year` is cut to "1".

**(c) Exact lengths leak call identity on unequal-length requests.**

Anonymous Dream agents reach 48.5% on the swap requests purely from lengths (Table 3; Qwen, which cannot see mask counts, reaches 0.6%). The paper handles this well for P1 with the equal-length subset (86.9 → 81.7). However, the abstract's "5.3 points" and the threshold result use all 400 requests.

### W3. Position agents vs numbered agents: the comparison is confounded and over-interpreted (Abstract; Sec. 3.2, 4, 5)

> "For the same model and the same lack of information about the others, a role given as a position works and a role given as a number does not." (Sec. 4)
>
> "while the same agents given their position on the whole skeleton reach 85.6%" (Abstract)

1. **Dream position agents are the canvas itself.** They are the canvas with the other calls' slots frozen as masks (`SkeletonConstraint(active_call=i)` and the sampler's `frozen` set). They are not prompted agents. On choose-N their identity with the k=16 canvas ("in all 105 requests") holds by construction: one-token slots all move in the first step from the same all-masked canvas.
2. **Qwen position agents do not see the whole skeleton.** `ar.generate_skeleton` decodes causally, so call i sees only the placeholders of calls 1..i-1. This contradicts "Position agents get the whole turn's skeleton".
3. **The numbered agents face a format mismatch.** They get a one-call skeleton while the system prompt says "If the question needs several calls, include all of them in the array" (PROMPTS.md). They also have one wording per protocol and are 7B models.

The comparison therefore contrasts a bidirectional model's positional marginals on its native n-call layout with instruction following in an off-distribution one-call prompt. It does not compare two encodings of the same role under the same input. Two further problems:
- "Not significantly different from its canvas" is ambiguous. Against the k=16 canvas, position agents are 3.8 points higher, bootstrap CI [1.0, 7.7], discordant 4/0, p=0.125.
- Several team results hold by construction: anonymous simultaneous agents with identical inputs collide 100% under greedy decoding. They are sanity checks, not findings.

### W4. Statistical inference is inconsistent where counts are sparse (Sec. 3.4, 4, 7)

**(a) Percentile bootstrap intervals and exact McNemar tests disagree.** In each case below the interval excludes 0 while the test does not reject. The paper picks whichever supports the narrative.

| Comparison | Difference [95% CI] | Discordant | McNemar p | Paper's wording |
|---|---|---|---|---|
| Dream position agents vs k=16 canvas | 3.8 [1.0, 7.7] | 4/0 | 0.125 | "not significantly different" |
| Dream canvas k=1 vs turn-anon | 3.8 [1.0, 7.7] | 4/0 | 0.125 | "do not differ significantly" |
| Dream CCER exact k=1 vs k=16 | -1.0 [-2.0, -0.3] | 0/4 | 0.125 | — |

**(b) The interaction rests only on a percentile bootstrap.**

> "Both factors matter, and they interact: parallel commits add 1.0 point with exact lengths but 3.8 with estimated ones (p = 0.0026; interaction 2.8 points, [0.3, 5.3])." (Sec. 7)

The p-value belongs to the simple effect, not the interaction. The interaction is not in the Holm family. Per request, the DiD takes values -1/0/+1 with counts 8/373/19, and an exact sign test gives p=0.052. Without Shared-only requests (W1a) the DiD is 1.25 points, 10/5, p=0.30 (my analysis).

**(c) The 48-test Holm family mixes confirmatory tests with tests that are determined by construction or pseudo-replicated.**
- Anonymous vs numbered agents, where anonymous agents have identical inputs.
- Open choose-N duplicates, k=16 vs k=1, 45/0. The 45 requests are 15 paraphrases × 3 values of n. Dream at k=16 gives one distinct output per n (`review_numbers.md`), so the effective n is about 3.

The family was evidently not fixed in advance.

**(d) The sampling claim rests on one temperature.**

> "sampling does not prevent it"

This is based on T=0.7 with five seeds and no intervals. At T=0.7, Qwen still picks the first city 99.8% of the time, so the claim says little about sampling as a symmetry breaker.

### W5. The "decider" and co-commit measure do not match their definition (Sec. 3.2, Sec. 4)

> "We call each slot a decider, since its first committed token usually decides which entity it names."
>
> "Dream commits the first tokens of 83.0% of its sibling slot pairs in the same step"

`co_commit.py` uses the commit step of the slot's first **position** (`sx[0]`). It does not use the first committed token. For integer and float slots the first position is the leading space, which the skeleton leaves to the model. The first committed token of a numeric slot is that space in 1,011/1,295 slots at k=1 and 1,202/1,295 at k=16. The space carries no entity information.

Using each slot's first content token (my analysis):
- The share falls from 83.0% to 74.9% (1,337/1,784).
- For numeric sibling pairs it falls from 93.6% to 77.9%.
- Only 41.7% of sibling pairs commit all their tokens in one step.
- The threshold figure is robust: 93.7% becomes 93.3%.

This does not overturn P1. In 160 of the 213 equal-length requests, every sibling group's first content tokens share one step and no other argument of those calls was committed earlier, so there is no within-call anchoring. On these 160 requests set accuracy is 81.9% at k=16 vs 86.9% at k=1. This strict test supports P1 and should be in the paper.

### W6. P3's mechanism needs refinement, and the delimiter isolation is imperfect (Sec. 3.3, 6; Table 3)

**(a) Length "fit" alone does not pull a slot to a sibling's value.**

> "a slot with a sibling's length gets that sibling's value, at any k" (P3)

With +1 on every slot, 249 slots get a length exactly equal to a sibling's value length. Only 2.0% of them (5) take that sibling's value; 63.1% overfill their own (my analysis). Compare 35.4% in "one slot longer" and 79.4% in the swap. The cue appears to be the slot's length relative to its siblings' slots, not an exact fit. This makes the result stronger and more interesting, but P3 and its interpretation should say so.

**(b) The closing-token-in-slot variant changes several things at once.**
- It adds one position.
- It fills the rest of the slot with spaces, where the default fills it with Dream's EOS (`pad_id = eos_token_id`, `adapters.py`). The default places EOS tokens mid-canvas, which is itself out of distribution and is not mentioned in the paper.
- It allows merged closers such as `",` and `}}`, which leave double delimiters on the canvas.
- 23.3% of its outputs do not parse at exact lengths, and 7.6% of slots never close.

Table 3's variant rows read slots "one by one", so unclosed overfills count as "overfill" in outputs that would fail. The probe comparison ("69.9% instead of 0.5%") also compares 1+s positions with s positions.

**(c) The training-mask premise is imprecise.**

> "In training every mask hides exactly one token, so the mask count always equals the length of what it hides." (Sec. 3.3)

Dream's and LLaDA's SFT pad responses with EOS, so trailing masks routinely hide padding. The claim holds only for masks followed by more text.

### W7. P2 evidence for the canvas is weak, and the open choose-N requests are poorly designed (Sec. 5, Table 2)

- **The canvas result does not survive correction.** Canvas duplicates are 15.0% (Holm p=0.059).
- **The baseline is weak.** "Fewer than independent uniform choices would (43.2%)" is a strawman; the relevant contrast is anonymous agents with identical inputs (100%).
- **"Cuts many names" is inaccurate for Dream.** Dream's 34.1% disallowed cities are the abbreviations "LA" and "NY", not cut names.
- **The one-token slot creates errors of its own.** Qwen splits one city across two calls (`('New','York','Los','An')`).

These open requests should not be in Table 2 or the test family.

### W8. Framing and AAMAS significance (Sec. 1–3, 9)

- The team-decision-problem framing is terminological only ("we use the terms only for who moves together and who sees what"). No model, prediction or optimality analysis comes from it.
- The multi-agent findings are mostly expected given the design: identical inputs collide, turn-taking avoids collisions, and 7B models given "assistant i of n" pick the first-mentioned entity.
- The most novel and solid contribution is the dLLM slot-length analysis. It matters to dLLM tool use but has limited multi-agent content.
- Order is measured against reference order rather than mention order. In at least `parallel_14` ("for 10, 20 and 30 years"; reference order 20, 30, 10) the model follows mention order and is counted out of order.

### W9. Reproducibility nits (supplement)

- **Stale stored diagnoses.** The supplement's records carry diagnoses from an older taxonomy, which `rediagnose.py` rewrites in place (e.g. 83 of 4,800 records in `dream/bfcl_surplus.jsonl`, 13 of 495 in `bfcl_swap`). Results reproduce only after this step.
- **Unscripted numbers.** Several in-text numbers come from no summary script: 59.3% (outside the type mask), 1,076 of 1,464, and 965 of 1,014. I recomputed them from `length_prior_s{1,2}.jsonl` (1,816/3,063 = 59.3%, 1,076/1,464, 965/1,014), and they match.
- **Two definitions of the one-slot-longer sibling share.** `closer.md` gives 35.4% (j\* only) and `swap_direction.md` gives 37.0% (any same-length sibling).
- **Stale docstrings.** `stats.py` refers to `release/results_2026-10-03.tar.gz`, and `reproduce_paper.sh` calls the probe "Figure 2c".
- **Unpinned dependencies.** `requirements.txt` pins no versions.

## 4. Questions for the authors

1. For each row of Table 4, how many CCER requests are Shared-only? Of those, how many are a single corrupted value or a forced optional default, and how many are genuine scope disagreements?
2. Why does the paper not report that 108/111 correct swap outputs are correct only as reordered sets? Would you add an order-sensitive rebinding rate (my count: 141/165)?
3. Why does the oracle skeleton include optional arguments with their reference defaults? What are Tables 1, 3 and 4 without the 315 such slots?
4. Can you show a scalar slot whose standalone token count is shorter than in context? I find none apart from 18 strings, while 122 array slots are one token longer.
5. Under uniform +1, only 2.0% of slots whose new length fits a sibling take that sibling's value, against 35.4% in "one slot longer". Is the cue the slot's length relative to its siblings' slots? Would lengthening i\* to len(j\*)+1 (no fit) give a similar pull?
6. What does the Dream position-agent comparison add beyond "the canvas with siblings kept masked"? Would numbered agents given the full n-call skeleton plus a note close the gap?
7. Which of the 48 tests were specified before the runs? Why are the identical-input and open choose-N tests in the family, and why is the interaction outside it?
8. Do the P2 results for teams hold at T=1.0 and above?
9. With surplus masks, how does left-to-right decoding behave? It would separate the length prior from out-of-order commitment within a slot.
