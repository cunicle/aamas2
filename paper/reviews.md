## P1：对称情形小实验
背景：“并行提交无害”的解释是提及顺序打破了对称性，
但对称无序恰恰是这个担心最强的版本，现在只放在局限里。
不测它，“我们检验了这个担心”就不成立。

构造 100 到 200 条：同一个函数、N 个实体（N=2、4、8），
实体不按顺序逐个列出（比如用隐含集合，或实体散在干扰句里）。
具体构造你来设计，先给我看 5 条样例。
s=0，k 取 1、4、16，加 AR 参照。
指标：set_acc、重复绑定率（两个槽写了同一个实体）、遗漏率。

两种结果都能写：
- 错误不随 k 上升：发现一成立，范围扩大。
- 错误随 k 上升：发现一改成“有顺序线索时并行无害，没有时会重复绑定”。
不要为了保住原论点调设置。

## P2：null token 基线
背景：S³（arXiv 2507.04504，ICLR 2026）引入 null token，
就是因为多余的槽会导致过度生成，所以现象本身不算新。
在 s=1、2、4、8 上加一组 S³ 式的 null token 对照，
和现有的收尾符号规则、收尾偏置 β 放进同一张表。
另外用两三句话写清楚：我们的收尾符号加强制 pad 和 null token 区别在哪。

## P3：free 模式进正文

模型自己生成骨架时的准确率，优先用已有结果。
目的是说明 oracle 骨架下的结论离真实场景有多远。

## 审稿 B（另一个 Opus）

这版比上一版好很多。 "先检验担心，发现不成立，再找出真正原因"这个写法是对的，结构也清楚。但动笔之前有四个问题要处理，最大的是新颖性。
`gpu-run` 上的最新提交（06b9c5d）只有代码，没有结果，所以下面的数字我核对不了，只能看论证本身。
1. 新颖性：发现二、三的一般形式已经有人发表了

* [Diffusion LMs Can Approximate Optimal Infilling Lengths Implicitly](https://arxiv.org/abs/2602.00476)：填空长度给多了，模型会用冗余或错误的 token 把格子填满。他们把这叫 Length Bias，和你们的"长度先验"几乎同名。
* [ρ-EOS](https://arxiv.org/abs/2601.22527)、DAEDAL：专门解决 dLLM 的变长生成。
* [S³](https://arxiv.org/abs/2507.04504)：大纲里已经引了，它用 null token 处理变长字段，等于已经把"槽长不对"当成问题并给了方案。

所以"模型把 mask 个数当长度""多给 mask 会被填满"不能当贡献。能当贡献的是这三点：

* 误归因：在并行工具调用里，长度问题表现为抄兄弟值、重复调用，看起来像并行解码的错，其实不是。
* 定量对比：k 从 1 到 16 的代价，对比多一个 mask 的代价。
* agent 场景下的严重程度。

相应要改两处：贡献列表里把发现二降为"在骨架约束下复现并测量"；§7 要讨论 null token、ρ-EOS 这些现成方案。β 偏置本质上是它们的简化版，审稿人一定会问为什么不比。
2. 发现一的证据还不够硬

* s=0 泄露了绑定信息。 s=0 时每个槽的长度就是它自己的值长度，长度本身就告诉模型哪个值属于哪个调用。大纲把这一点放在局限里，但它其实是发现一的直接替代解释。CCER 要在长度对称的兄弟组上单独报告，代码里已经有 `length_symmetric()`。
* "提及顺序给了位置先验"没有实验支撑。 局限里还写了"对称无顺序的情形没测"。两个选择：
   * 测一下：把骨架里调用的顺序和请求里的提及顺序打乱，看 CCER 变不变；
   * 或者改成"我们推测"。
* 论点改成比较式更稳。 pilot 里 LLaDA2.0 在 k=16 时 CCER 6.2%，set_acc 掉了 10 个点。与其写"几乎无害"，不如写"并行度的代价比长度错配小一个数量级"。这样即使 k 有一点影响，论点也站得住。

3. 发现三：要等数据，有两处要提前防

* 0.9→0.1 要配上单槽准确率。 set_acc 要求一个条目里所有调用全对，每条有好几个槽，单槽错误会被放大。只报 set_acc，看起来像是指标在放大。
* "多数错误来自抄兄弟值"和图 1 的例子对不上。 "Taylor Swift. Swift" 是自我重复，不是抄兄弟。
   * 统一加 s 时，多出的格子一般装不下兄弟值，错误更可能是"写长"，也就是单调用错误。
   * 抄兄弟值主要出现在"同参数取最长"的槽长下，就是之前那 18 个错误里的 17 个。
   * 如果错误构成表显示大部分是写长，跨调用这个角度就弱了，论文会退化成"dLLM 会把槽填满"，和上面的已有工作更难区分。
* 补上长度互换实验。 这就是我上次建议它的原因：它直接检验"模型按长度把值绑到调用上"，是把长度先验和跨调用错误连起来的那一环。只需要长度不同的兄弟组、k∈{1,4}，很便宜。
* "AR 不受影响"要写成设计上的性质。 AR 遇到收尾符号就停，富余格子按实现就影响不到它，这不是实验发现。
* 引言要先回答"误差是你们自己造出来的吗"。 实际系统不知道取值长度，任何骨架方法都得猜槽长，所以长度错配是常态，不是人为设定。这一点要在引言里先说清楚。
